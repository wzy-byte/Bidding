# 招投标学习知识库

> 一名前端开发在 AI 招投标项目组里的知识沉淀。周期：2026 年 11 月 — 2027 年 4 月。
> 目标不是背法条，而是**把条文翻译成界面行为，并能说明依据**。

---

## 这是什么

围绕 AI 招投标产品建设整理的学习资料、条文笔记、流程视图与技术实现记录。

分类原则只有一条：**按「下次来找它是为了做什么」分类，不按学科，也不按月份。**

按学科分（法律 / 流程 / 技术）看起来整齐，但真到写需求时不知道该翻哪一栏；按月份分更糟，三个月后完全想不起来里面装了什么。

## 归类判定顺序

从上往下，**第一个命中就放那里**，不需要犹豫：

1. 别人写的原文 → `02-原文`
2. 我对某一条的理解 → `03-条文笔记`
3. 多条拼起来的时间线 / 状态机 / 时限表 → `04-流程与时限`
4. 产品该做什么、AI 场景、规则库设计 → `05-场景与产品`
5. 代码、组件、接口、安全与性能实现 → `06-技术实现`
6. 真实项目样本、我交付的成果 → `07-实战与产出`
7. 本月学了什么、考核、绩效材料 → `08-复盘与考核`
8. 还没想清楚 → `01-收件箱`

---

## 三条硬规则

1. **原文永不改写**。`02-原文` 里放的就是下载来的原样，笔记里写「依据：实施条例第 26 条」，不把原文复制进笔记再改。
2. **同一份内容只存一处**。`04` 只放跨条文的汇总视图，单条规则永远留在 `03`，用链接引用。两处维护必然不一致，而在招投标里「不一致」就是错。
3. **月份不进目录**。月份只出现在 `08` 的文件名里，计划会结束，知识要能继续用。

## 每条笔记的头部

```yaml
---
类型: 条文笔记
法规: 招标投标法实施条例（国务院令第709号）
条款: 第26条
主题: 投标保证金
关联流程: 投标
关联场景: 保证金校验
状态: 已精读
更新: 2026-11-15
---
```

`状态` 只走单向：`待读` → `已读` → `已精读` → `已用于产品`。最后这个状态证明学习已经变成产品里的一行校验、一条提示。

## 依据与时效

本库引用的法规以发布机关官网公开文本为准，具体条款适用前须回查原文；涉及产品合规的判断，以公司合规与法务口径为准。

两点必须区分：

- **现行有效**与**草案**要分开标注。2026 年 6 月首次审议的《招标投标法》修订草案（6 章 79 条）尚未通过，只能用于判断趋势，对外文案不得写成「已施行」。
- **地方文件有有效期**。`合公信〔2025〕82 号`（合肥公共资源交易大模型办法）自 2025-11-23 施行、有效期一年，到期前后须确认续期或修订。

## 维护节奏

- **周五**：清空 `01-收件箱`，按判定顺序归类；写一句话复盘进 `08`。
- **月末**：更新进度表；核对 `00-索引/法规清单.md` 的变动（新增、修订、废止、地方办法到期）。
- **每季度**：把仍标为 `已读` 的卡片翻一遍，能升级的升级，读不懂的写下具体卡在哪。
